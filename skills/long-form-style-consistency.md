# Long-Form Style Consistency Audit

## Aim

Keep a manuscript or large report coherent when its parts were written months apart,
by different model versions, or under changing prompts. Detect and repair unsupported
style and character drift without flattening every chapter, speaker, or section into
one average voice.

## Activation Gate

Use for a multi-chapter, multi-section, or otherwise oversized draft when the user
requests long-form review, chunked audit, writing-style unification, 文风统一, 分块审查,
长篇审查, 跨章一致性, or character-setting consistency. Do not load it for an ordinary
short passage. An explicit reference sample or approved manuscript block may define
style; character canon requires an outline, character bible, continuity ledger, or
clear prior-text evidence.

## Evidence Authority

Keep these sources separate and resolve conflicts in this order:

1. user corrections and canonical outline or project ledger
2. explicit approved style contract or supplied style references
3. confirmed change logs and the latest relevant chapter state
4. earlier approved manuscript passages
5. local inference, marked uncertain

Reference prose controls transferable style only. It cannot overwrite plot, facts,
characters, findings, terminology, or conclusions. A polished but unapproved recent
block must not silently become the baseline merely because it was produced last.

## Baseline Contract

Build a compact contract from evidence rather than a list of banned words:

- narrator or institutional voice, viewpoint, distance, and formality
- sentence and paragraph range, pause habits, transition method, and closure pressure
- diction, repetition tolerance, imagery load, description order, and explanation density
- dialogue turn length, address forms, directness, subtext, fillers, interruptions, and silence
- for each character: goals, knowledge, relationships, boundaries, stable behavior,
  speaker markers, and valid development gates
- for serious prose: terminology, claim strength, attribution, citation behavior,
  section function, and protected factual spans

Treat numeric style statistics as triage evidence, not targets. Do not mechanically
equalize sentence length, vocabulary diversity, dialogue ratio, or paragraph size.

## Chunk Protocol

Partition the draft at chapter, paragraph, or sentence boundaries. Each body span is
audited exactly once. A short tail from the preceding block may be included as a
read-only lead-in so the new block has causal and tonal orientation; do not issue a
duplicate finding based only on that lead-in.

For each body span:

1. Compare it with the baseline contract and canonical outline.
2. Separate global drift from variation earned by viewpoint, scene pressure, elapsed
   time, genre function, quoted material, or deliberate character development.
3. Locate narrator drift, speaker drift, character-state conflict, terminology drift,
   and section-purpose drift with evidence.
4. Recommend the smallest local repair. Preserve facts and intentional development.
5. Emit only the state and voice changes that later blocks need.

Do not carry full prose summaries from every block. Reconcile compact evidence records:

```text
block and location -> baseline or canon -> observed form -> valid change gate
-> confirmed drift / intentional range / uncertain -> minimal repair -> ledger delta
```

## Outline-Backed Character Check

An outline is a source of canon, not a magic memory substitute. Convert relevant parts
into character cards and update them only through established events. Check behavior,
dialogue, knowledge, capability, loyalties, boundaries, and relationship state separately.
If the outline gives only a broad adjective, do not force every line to perform it.
Scene goal, listener, risk, public/private posture, fatigue, and deception may vary the
surface voice while the underlying character remains consistent.

## Cross-Chunk Reconciliation

After independent chunk passes, compare findings across at least two relevant blocks,
except for a direct contradiction with canon. Revisit revision boundaries and middle
sections, where model or prompt changes are often most visible. Repair in this order:

1. facts, chronology, claim meaning, and canonical character state
2. character motivation, knowledge, relationship, and dialogue voice
3. narrator or institutional voice and section function
4. rhythm, transitions, imagery, and surface wording

Re-audit neighboring blocks after a structural change. Record approved evolution in
the ledger so a valid new voice is not repeatedly "corrected" back to an obsolete state.
