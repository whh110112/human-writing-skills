# 确定性写作痕迹扫描

`lint` 针对可观察的文字模式给出规则编号、严重程度、行列、字符区间、原文证据和
修改方向。

```powershell
human-writing-skills lint --draft chapter.md --style fiction
human-writing-skills lint --draft report.md --style academic-paper --format json
human-writing-skills lint --draft chapter.md --allow PREC001 --fail-score 35
```

检查内容包括夸大词汇、万能身体动作、空洞氛围、公式化转折、死转场、聊天助手
残留、宣传腔、叠加模糊词、假精确数字、模糊归因、假范围、同义词轮换、排版习惯、
句长过度整齐和破折号密度。`STR001` 覆盖“不是 X，是 Y”和“是 X，不是 Y”两个
方向；同句两个有效“比”分句触发中风险 `STR002`，三个以上在非论文、非新闻文体
中触发高风险 `STR004`；`STR003` 只在对举框架跨段高密度复现时升级。这些规则
要求结合语境复核，不会自动删句。小说、网文和自媒体还会检查密集比喻（`IMG001`）、连续四个
以上短段（`PARA001`）、履历式资料倾倒（`INFO001`）以及动作后重复解释同一情绪
（`EMO002`）；这些规则不会套到论文和新闻上。代码、链接和 Markdown 引文不会
参与扫描。新增规则还会定位电影式开场堆料（`OPEN002`）、反复使用模糊的内心
自我解释（`EMO003`）以及多章连续从天气、光线和穿着重新开场（`RESET001`）。
`SYN001` 只定位“把、被、向、从、因为、如果”等结构词停在句末的高置信缺失
症状；更复杂的漏字仍由 `proofread` 按谓词槽位、并列结构和指代关系复核。

对 `fiction` 和 `webnovel`，`END001` 只检查场景或全文出口。它要求风景/时间渐隐、
刻意静止、人物反思、主题总结等多个信号在最后有效变化之后组成反思式尾巴；单个安静
意象或一次合理思考不会因为出现某个词就被判定。修复先做删除测试，不把它机械换成
悬念句或另一套漂亮收束。

扩展的表层模式家族还包括意义拔高（`SIGN001`）、模糊归因（`ATTR001`）、
公式化“挑战与未来”收尾（`CHALLENGE001`）、英文复杂系词（`COPULA001`）、装饰性
分词（`ING001`）、假范围密度（`RANGE001`）、拔高词簇（`LEX003`）、叙事中的
同义称呼轮换（`ALIAS001`）以及重复排版模板（`FORMAT001`-`FORMAT003`）。多数
规则看复现密度，单次合理使用不会变成禁词。

对 `fiction` 和 `webnovel`，`HEAD001` 检查叙事正文中未要求的 Markdown 小标题或
独立加粗标签；`HEAD002` 检查中文、英文、日文、法文、西班牙文、葡萄牙文、
阿拉伯文和拉丁文的独立时间卡。作品标题和真正的章节标题保留，新闻、论文、
议论文和自媒体的结构标题不进入这两条规则。修复不能只删标题，而要补回“上一场
残留 -> 时间或条件变化 -> 新场景首个动作”的正文桥接。明确要求日志、档案、书信、
剧本或分节体例时可用 allowlist 放行。

这些规则检查的是结构是否被滥用，不是禁用单字。事实纠错、法律排除、科研比较、
人物反驳和故意残句可以保留。修改时应改变信息路径：直述事实、补证据、统一比较
标准或拆开不同标准，而不是把“不是”机械换成“并非”。

分数是透明、可重复的编辑启发式，不是 AI 作者身份的证据。每个命中都需要结合
语境人工判断，有意保留的规则可用 `--allow` 放行。`pipeline` 会在模型审稿文件前
自动生成 `00-pattern-lint.md` 和 JSON。

可选文体统计和保守机械修复见 [editing-tools.zh-CN.md](editing-tools.zh-CN.md)。
