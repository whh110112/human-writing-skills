# 长篇分块审查、文风统一与人物设定统一

这套流程用于小说、系列文章、研究报告、年度报告、技术文档等大体量文本。它解决的不是
“把全文切成几段分别润色”这么简单，而是让所有分块共享同一份可核验的文风基准、人物设定
或报告规范，再把局部审查结果汇总为跨块问题。

适合搜索词：**长篇审查、分块审查、文风统一、统一文风、人物设定统一、人物一致性审查、
跨章一致性、小说审查、报告审查、长文上下文一致性**。

## 为什么普通分块仍会漂移

如果每一块只看到本块正文，模型会重新猜测叙述距离、句子节奏、人物口吻和术语习惯；如果
把整部作品和全部审查模块反复塞入，又会浪费 Token 并挤压真正需要推理的上下文。
`chunk-audit` 使用三层材料：

1. **基准证据**：明确输入的参考样文优先；没有参考样文时，由用户指定一个候选正文块并在基准提取阶段确认。
2. **权威设定**：小说使用大纲、人物小传或连续性账本；报告使用章节计划、术语表、结论边界和来源约束。
3. **当前分块**：正文字符只进入一个审查块；上一块末尾仅作为只读衔接区，不重复报错。

## 基本命令

```powershell
human-writing-skills chunk-audit `
  --draft full-novel.md `
  --style fiction `
  --outline novel-outline.md `
  --output-dir novel-consistency-audit
```

也可以明确指定已认可的旧稿作为文风基准：

```powershell
human-writing-skills chunk-audit `
  --draft annual-report.md `
  --style formal-document `
  --context report-plan.md `
  --reference approved-2025-report.md `
  --chunk-size 10000 `
  --output-dir report-style-audit
```

没有 `--reference` 时，默认把第一个分块当作候选基准，使用前应先确认。若第一块并不典型，
可用 `--baseline-chunk 3` 指定其他块。参考材料只决定可迁移的表达特征，不会覆盖小说事实、
报告结论或人物设定。

## 输出文件

- `00-baseline-prompt.md`：先提炼紧凑的文风合同、人物卡或报告规范。
- `00-style-drift.md/json`：确定性统计比较，用来定位值得复核的块，不代表缺陷或作者身份。
- `0001-chunk-audit.md` 等：逐块独立审查。块首带少量只读前文，避免断裂但不重复计数。
- `9999-reconcile-prompt.md`：汇总跨块文风漂移、人物对白变化、术语变化和有效演变。
- `manifest.json`：记录每块的唯一正文范围、只读衔接范围和基准来源。

按 `00-baseline`、编号分块、`9999-reconcile` 的顺序运行。每个编号分块可以放入新的模型
会话或独立 API 请求；把已经确认的基准合同一并提供即可，不需要让模型记住整部作品。

## 如何依托大纲保证人物统一

大纲不是一句“他很阴沉”就能约束所有对白。流程会从大纲或账本提取：目标、知识、关系、
边界、能力、公开姿态、私下压力、常用称呼、直接程度、隐瞒方式和有效变化事件。审查时先问：

```text
大纲或账本中的状态 -> 当前块的行为/对白 -> 中间是否存在变化事件
-> 矛盾、有效成长、刻意表演，还是证据不足
```

角色可以成长、撒谎、伪装或因听众不同而调整语气；但这些变化必须有情节依据。确认后的变化
写回账本，后面的块采用新状态，避免把人物永远锁死在开篇设定里。

## 文风统一不等于机械拉齐

不同章节和报告部分承担不同功能，句长、对白比例和信息密度本来就会变化。统计文件只负责
指出明显偏移，模型审查还要判断偏移是否由视角、场景压力、引用材料、章节功能、时间跨度或
人物成长造成。只有缺少依据的变化才需要修复。

修复顺序应当是：事实与结论边界 -> 人物状态与动机 -> 人物对白/机构口吻 -> 节奏和转场
-> 表层用词。大改后重新审查相邻两个块，防止局部统一反而制造新的衔接问题。

## Token 控制

- 默认正文块约 8000 字符，只读衔接约 600 字符。
- 大纲/账本默认最多抽取 6000 字符，文风基准默认最多 4000 字符。
- 小说只有提供大纲/账本时才加载权威人物一致性模块；有对白的块才追加对白声音审查。
- 新闻、论文、公文等不会加载小说人物和对白规则，而会加载不可改内容保护。
- 需要更小上下文时降低 `--chunk-size`、`--context-budget` 或 `--baseline-budget`，但不要把
  分块缩得失去完整场景或论证单元。
